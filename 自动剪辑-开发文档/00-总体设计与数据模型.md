## 1. 需求一句话

用户选择**货号**、粘贴**文案** → 系统从素材库（按货号 + 通用素材）自动挑选画面，按时长拼接成粗剪视频。素材为影棚无声产品视频，**单条即最小镜头单元，通常 1-5 秒**。

## 2. 决策记录（已确认，后续阶段不重复讨论）

| # | 决策 | 内容 |
| --- | --- | --- |
| D1 | 素材必填属性 | 货号 + 分类。分类初始三条：文胸 / 内裤 / 通用；用户后续可新建分类（P2 提供管理入口） |
| D2 | 通用的定义 | **不露出产品的画面**（穿衣动作、场景氛围、过渡镜头）。它是与文胸/内裤并列的分类，不是"兜底池" |
| D3 | 通用素材的货号 | 表单选"通用"分类后货号自动填哨兵值 `"通用"`，保持两字段必填约束不破 |
| D4 | 初版匹配范围 | 只匹配 `货号 = 目标货号` 的素材 ∪ `分类 = 通用` 的素材，纯结构化 SQL 过滤，**不依赖 embedding** |
| D5 | AI 打标职责 | 货号=人工填写（事实数据）；AI 负责：分类预测辅助、**露产品检测**（防串款事故）、景别/动作/画面描述 |
| D6 | 无镜头切分 | 素材即最小单元，文件=镜头。入库流水线：ffprobe 读时长 → 抽中间 1 帧 → VLM 打标 |
| D7 | 一句多段 | 时间线最小结构为"句子 → N 段素材顺序拼接"。1-5 秒素材对 4-15 秒句子，多段是常态 |
| D8 | 慢放/循环 | 从方案中移除。素材不够靠"多挑一条"，缺口如实上报 |
| D9 | 缺口可视化 | 匹配不到/凑不够时长的句子在时间线上标红并给出缺口明细，素材库提供按货号×分类的统计 |
| D10 | 批量上传 | 素材是海量小文件，上传必须批量：多选文件 + 统一填货号+分类，打标异步消化（批次概念入表） |
| D11 | 拆句带分类判定 | 每句输出"需要什么分类的画面"，分类清单从数据库动态注入 prompt，用户新建分类后自动生效 |

## 3. 架构与代码挂载点

沿用"壳 + 模块"结构，**不引入新基建**。Electron 壳已存在（`canvas-two/electron/`）。

### 前端

```
web/src/modules/video-edit/
├── index.ts          # registerModule({ id: "video-edit", routes, nav, home })
├── pages/
│   ├── home.tsx      # 已有占位页
│   ├── materials.tsx # 素材库（P1）
│   ├── create.tsx    # 创作页（P1）
│   └── exports.tsx   # 导出/历史（P1）
└── store.ts          # 本模块自己的 zustand store
```

- 注册方式照抄 `web/src/modules/registry.ts` 的 `registerModule` 约定：路由组件必须 `React.lazy`，禁止跨模块 import。
- API 调用放 `web/src/modules/video-edit/api.ts`，用共享层带 token 的 axios 实例。

### 后端

```
server/src/video/
├── routes.ts    # Express Router，挂载到 index.ts：app.use("/api/video", videoRouter)
├── llm.ts       # AI 通道解析（仿 kb/llm.ts）：kind = "chat" | "vision"
├── ingest.ts    # 批量入库 + 打标 worker 逻辑（start/stop 模式，仿 kb/indexer.ts）
├── split.ts     # 文案拆句（chat LLM + structured output）
├── match.ts     # 候选池过滤 + 组合匹配（chat LLM）+ 缺口检测
├── export.ts    # ffmpeg 合成 worker
└── ffmpeg.ts    # ffmpeg/ffprobe 二进制定位与 spawn 封装
```

- 异步任务（打标、合成）在独立 worker 进程内以轮询方式执行（`worker.ts` 里新增 `startVideoJobs()`），与现有图片任务、kb indexer 同进程共存。HTTP 路由只写表、查状态，不阻塞。
- 校验统一用 zod（已有依赖）。

### ffmpeg 二进制定位

不引入 fluent-ffmpeg 之类的库，直接 `spawn`。解析顺序：

1. 环境变量 `FFMPEG_PATH` / `FFPROBE_PATH`
2. 仓库/安装目录下 `tools/ffmpeg(.exe)`、`tools/ffprobe(.exe)`
3. 系统 `PATH`

开发期用 PATH 或放一份到 `tools/`；Electron 打包时随 `resources/` 分发（P3 处理）。

### 删除模块即回退（解耦验收）

删 `web/src/modules/video-edit/` 目录 + `index.ts` 中 `app.use("/api/video", ...)` 一行 + `worker.ts` 中 `startVideoJobs` 两行，项目照常编译运行。

## 4. 数据模型（Prisma 草案）

命名遵循现有 snake_case 映射约定。共 7 张表，全部带 `video_` 前缀。

```prisma
// 分类：初始 seed 文胸/内裤/通用（isSystem=true）。通用分类不可删除、不可改名。
model VideoCategory {
  id        String          @id @default(uuid())
  name      String          @unique
  isSystem  Boolean         @default(false)
  sortOrder Int             @default(0)
  createdAt DateTime        @default(now()) @map("created_at")
  materials VideoMaterial[]

  @@map("video_categories")
}

// 上传批次：一次批量上传 = 一条批次，页面上用它展示打标进度
model VideoIngestBatch {
  id           String          @id @default(uuid())
  sku          String
  categoryId   String          @map("category_id")
  createdById  String          @map("created_by_id")
  totalCount   Int             @map("total_count")
  doneCount    Int             @default(0) @map("done_count")
  failedCount  Int             @default(0) @map("failed_count")
  status       String          @default("processing") // processing / done / partial / failed
  createdAt    DateTime        @default(now()) @map("created_at")
  category     VideoCategory   @relation(fields: [categoryId], references: [id])
  materials    VideoMaterial[]

  @@map("video_ingest_batches")
}

// 素材：文件即镜头，单表搞定（不再有 VideoShot 层）
model VideoMaterial {
  id               String            @id @default(uuid())
  batchId          String?           @map("batch_id")
  mediaFileId      String            @map("media_file_id")    // 原视频，MediaFile.origin = "video"
  thumbnailMediaId String?           @map("thumbnail_media_id") // 抽帧缩略图，也是 MediaFile
  sku              String            // 货号；通用素材为哨兵值 "通用"（D3）
  categoryId       String            @map("category_id")
  fileName         String            @map("file_name")
  duration         Float             // 秒，ffprobe 读取，入库必填
  width            Int?
  height           Int?
  tagStatus        String            @default("pending") @map("tag_status") // pending / done / failed
  tagError         String?           @map("tag_error")
  description      String?           // 一句话画面描述（VLM）
  shotType         String?           // 景别：特写 / 近景 / 中景 / 全景
  motion           String?           // 动作：旋转 / 手持 / 摆放 / 穿戴 / 平铺 ...
  productVisible   Boolean?          @map("product_visible") // 画面是否露出产品（通用素材安全校验，D5）
  reviewStatus     String            @default("none") @map("review_status") // none / warn_confirmed / corrected（P2 复核队列用）
  useCount         Int               @default(0) @map("use_count") // 被时间线采用次数（P3 运营）
  status           String            @default("active") // active / archived
  createdAt        DateTime          @default(now()) @map("created_at")
  batch            VideoIngestBatch? @relation(fields: [batchId], references: [id])
  category         VideoCategory     @relation(fields: [categoryId], references: [id])

  @@index([sku, categoryId, status])
  @@index([tagStatus])
  @@map("video_materials")
}

// 文案：原始文本 + 拆句结果
model VideoScript {
  id        String           @id @default(uuid())
  title     String
  sku       String           // 目标货号（成片围绕它）
  rawText   String           @map("raw_text") @db.Text
  sentences Json?            // SentencePlan[]，见 §5
  status    String           @default("draft") // draft / split / matched
  createdAt DateTime         @default(now()) @map("created_at")
  timelines VideoTimeline[]

  @@map("video_scripts")
}

// 时间线：一句多段的匹配结果（D7）
model VideoTimeline {
  id        String             @id @default(uuid())
  scriptId  String             @map("script_id")
  version   Int                @default(1)   // 人工调整时 +1，可追溯
  items     Json               // TimelineItem[]，见 §5
  gapReport Json?              @map("gap_report") // GapReport，见 §5
  status    String             @default("matched") // matched / edited / exporting / exported / failed
  createdAt DateTime           @default(now()) @map("created_at")
  script    VideoScript        @relation(fields: [scriptId], references: [id])
  exports   VideoExportTask[]

  @@map("video_timelines")
}

// 导出任务：worker 轮询执行
model VideoExportTask {
  id            String         @id @default(uuid())
  timelineId    String         @map("timeline_id")
  params        Json           // { resolution, fps, crf, burnSubtitle, ... }
  progress      Int            @default(0) // 0-100
  status        String         @default("queued") // queued / running / succeeded / failed
  error         String?
  outputMediaId String?        @map("output_media_id") // 成片 MediaFile
  createdAt     DateTime       @default(now()) @map("created_at")
  startedAt     DateTime?      @map("started_at")
  finishedAt    DateTime?      @map("finished_at")
  timeline      VideoTimeline  @relation(fields: [timelineId], references: [id])

  @@index([status, createdAt])
  @@map("video_export_tasks")
}

// 模型渠道设置：仿 KbSetting，管理员在设置页指定拆句/匹配模型与打标视觉模型
model VideoSetting {
  id              String  @id // 固定 "default"
  chatChannelId   String? @map("chat_channel_id")
  chatModel       String?
  visionChannelId String? @map("vision_channel_id")
  visionModel     String?

  @@map("video_settings")
}
```

Seed：`文胸`、`内裤`、`通用` 三条 `isSystem=true` 记录（migration 或首次启动幂等写入）。

与现有表的关系：只关联 `MediaFile`（视频原件、抽帧缩略图、成片都走 MediaFile，`origin="video"`，享受现有 MinIO 存储与清理链路）。**不**关联 User 新外键之外的业务表。

## 5. 核心 JSON 结构

### SentencePlan（拆句输出，存 VideoScript.sentences）

```json
{
  "sentenceId": 1,
  "text": "这款无钢圈文胸，久穿不勒",
  "needCategory": "文胸",        // 动态分类清单中的某一个；通用=用通用素材
  "durationHint": 4.5,           // 预估时长（秒），按 4~5 字/秒估算
  "visualNote": "上身贴合效果，或无钢圈边缘特写"  // 给匹配环节的画面提示
}
```

判定规则（写进拆句 prompt）：产品卖点句（面料/工艺/版型/上身效果）→ 产品所属分类；穿搭动作、场景氛围、开场结尾引导 → `通用`。

### TimelineItem（时间线单元，存 VideoTimeline.items）

```json
{
  "sentenceId": 1,
  "subtitle": "这款无钢圈文胸，久穿不勒",
  "needCategory": "文胸",
  "duration": 4.5,               // 本句总时长 = durationHint（P2 接 TTS 后 = TTS 实测时长）
  "segments": [
    { "materialId": "uuid", "inPoint": 0.0, "outPoint": 2.1, "reason": "上身侧面贴合" },
    { "materialId": "uuid", "inPoint": 0.0, "outPoint": 2.4, "reason": "无钢圈细节特写" }
  ],
  "downgraded": false            // true=该句用了同货号其他分类的素材顶替（候选链降级）
}
```

约束：段按顺序播放；`inPoint=0、outPoint=素材时长`（整条使用），仅最后一段允许裁剪以对齐句子总时长；所有段时长之和 ≈ `duration`（±0.3s）。

### GapReport（缺口报告，存 VideoTimeline.gapReport）

```json
{
  "items": [
    {
      "sentenceId": 3,
      "kind": "no_candidate",      // no_candidate=候选池空 / insufficient=凑不够时长
      "needCategory": "文胸",
      "detail": "货号 A123 无『文胸』分类素材",
      "missingSeconds": 0          // insufficient 时给出差多少秒
    }
  ]
}
```

有缺口的句子 `segments` 可以为空（如实上报，不硬凑，D8）；导出时跳过该句或占黑场（P1 选择：跳过，字幕也跳过）。

## 6. 匹配流水线（各阶段共用逻辑）

```
候选池（SQL，结构化过滤，D4）：
  句子.needCategory = "通用"  →  { sku: "通用", status: "active", tagStatus: "done" }
  否则（目标货号 X）           →  第一层：{ sku: X, categoryId: 对应分类 }
                                 第二层（降级）：{ sku: X }（任意分类，标 downgraded）
                                 第三层：空 → gap

组合匹配（chat LLM）：
  输入 = SentencePlan[] + 候选素材清单（id / 分类 / 时长 / description / shotType / motion）
  输出 = TimelineItem[]（一句多段、整条使用、末段微调、理由）
```

候选清单控制：P1 直接全量塞 prompt（每条约 50 token，几百条无压力）；超过 500 条时先按 `needCategory` 对应分类过滤，仍超则按 `useCount` 降序取前 300（P3 换 embedding 召回）。

## 7. AI 通道（复用 ModelChannel）

`video/llm.ts` 仿照 `server/src/kb/llm.ts`：

- `resolveVideoModel("chat" | "vision")`：读 `VideoSetting`，未配置时自动挑第一个可用的 OpenAI 兼容 text / vision 渠道。
- chat：DeepSeek（或任何 OpenAI 兼容对话模型），拆句 + 匹配决策。
- vision：Qwen-VL 等（DashScope / ark 等 OpenAI 兼容入口），打标。
- structured output 统一策略：`response_format: { type: "json_object" }` + zod 校验 + 失败带错误重试 1 次，仍失败则任务标 failed 并透出原因。
