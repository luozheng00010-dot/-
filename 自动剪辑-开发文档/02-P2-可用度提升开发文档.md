# P2 · 可用度提升开发文档

> 前置：P1 已交付粗剪闭环。P2 的主题是**把"能出片"变成"出的片能用"**：人工可控性（时间线编辑、校准）、观感（TTS、字幕样式、BGM）、素材运营（缺口统计、复核队列、分类管理）。
> 工期估算：2-3 周（1 人全职）。功能块相互独立，可按优先级裁剪排期，建议顺序：F1 → F2 → F5 → F3 → F4 → F6。

## 1. 验收标准

1. 时间线支持：换素材（从候选列表挑）、调段顺序、拖拽调句/段时长、删句加句、**单句重匹配**；保存后 version+1，历史版本可回看。
2. 接 TTS 后：成片带旁白，每句画面时长 = 该句旁白实测时长，音画对齐误差 ≤0.1s。
3. 字幕可选 3 套预置样式；BGM 可选库内音乐并自动压低（ducing）至旁白之下。
4. 素材库出现"复核队列"：露产品黄标素材集中处理，确认安全的才继续参与通用匹配。
5. 缺口统计页：货号 × 分类矩阵，一眼看出哪个货号缺哪类素材；点击格子跳转筛选列表。
6. 管理员可新建/停用自定义分类（"通用"与系统分类不可删改）；新建后立即出现在上传表单与拆句判定里。

## 2. 功能块

### F1 时间线编辑器（前端为主，约 5d）

- 页面：创作页步骤 3 从只读升级为编辑态，或独立 `/video-edit/timeline/:id` 页（推荐独立页，URL 可分享）。
- 交互清单：
  - 段卡片：点击弹出**候选替换面板**（该句候选池内素材网格，按匹配度排序——P2 的"匹配度"就是 LLM reason 的简单文本相似 + 分类匹配，不做 embedding）；
  - 拖拽：句卡片上下调序（React DnD / dnd-kit，与画布模块的技术选型对齐，看 shared 里有没有现成的）；段时长用数字步进器（拖拽精调到帧级是 P3 的打磨项）；
  - 删除句/段；手动添加段（从素材库搜索挑选）；
  - **单句重匹配** `POST /timelines/:id/rematch`：带 sentenceId，只重跑该句的匹配，其余句子原样保留；
  - 播放预览：P2 用 `<video>` 顺序播放各段近似预览（不做实时合成），够用即可。
- 保存：`PUT /timelines/:id` 全量覆盖 items，version+1；服务端跑与 P1 相同的 zod 业务校验（materialId 合法性、时长和）。
- 导出沿用 P1 任务流，编辑态保存的 timeline 才可导出。

### F2 TTS 旁白（后端为主，约 3d）

- 选型：edge-tts 起步（免费、中文音色可接受、无 key），封装成 `video/tts.ts`，接口签名与后续替换火山引擎 TTS 兼容（同输入文本+音色，返回 mp3 路径与时长）。
- 流程：`POST /scripts/:id/tts` → 逐句生成旁白 mp3 → **ffprobe 实测每句时长** → 重写 sentences 的 durationHint=实测值 → 已有时间线按新时长重新分配段（整条素材不动，只动最后一段出点；仍不够的句子进 GapReport）。
- 合成改造（export.ts）：逐段混音改为——拼接 body.mp4 后，把各句旁白按起止时间混成一条音轨 `adelay+amix`，再与 BGM（F3）混合。
- 存储：旁白 mp3 存 MediaFile（origin="video"），句级文件名 `{scriptId}_{sentenceId}.mp3`。
- 注意：edge-tts 是非官方接口，偶发限流；任务内失败重试 2 次并在结果里标注哪句没配上（fallback：该句无旁白、时长回落到字数估算）。

### F3 字幕样式 + BGM（约 2d）

- 字幕：3 套预置 ASS 样式（极简白/强调黄/黑底白字条），存为服务端模板参数（字号、颜色、边框、MarginV），导出时按 params.subtitleStyle 渲染；不支持用户自定义样式（P3 再说）。
- BGM：`server/assets/bgm/` 放 3-5 首可商用音乐（注意版权来源并留 LICENSE 说明），导出参数选曲 + 音量；混音 `sidechaincompress` 或简单 `volume=0.15`（旁白存在时 BGM 恒定低音量，P2 不做动态 ducking，够用）。
- params schema 扩展：`{ burnSubtitle, subtitleStyle: "minimal"|"highlight"|"bar", bgm: "none"|assetId, bgmVolume }`。

### F4 打标校准 + 露产品复核队列（约 3d）

- 复核队列（素材库子页 `/video-edit/materials?review=1`）：列出 `productVisible=true && 分类=通用` 的素材；动作二选一：
  - **确认安全**（`reviewStatus=warn_confirmed`，实际无产品/可接受）：继续参与匹配；
  - **改判**：改分类到具体货号分类或归档（`corrected` / `archived`）。
- 规则升级：`productVisible=true && reviewStatus=none` 的通用素材**不进入**匹配候选池（P1 是黄标不阻断，P2 收紧；这是串款事故的硬闸门）。
- 校准编辑：素材详情抽屉可改 description / shotType / motion / 分类 / 货号（`PATCH /materials/:id` 已有，补前端）。
- 批量重打标：选中素材重新走 VLM（复用 ingest worker，置 tagStatus=pending）。

### F5 缺口统计视图（约 1.5d）

- `GET /materials/stats`：按 sku × category 聚合 active 且 tagStatus=done 的条数与总秒数。
- 前端：矩阵热力表（行=货号，列=分类，格=条数/秒数，低于阈值标黄/红——阈值先拍：条数<5 或 秒数<30 标红）。点格子带筛选跳转素材列表。
- 价值：补拍清单直接从这张表来，这是运营侧最常用的页面。

### F6 分类管理（约 1.5d）

- `POST /categories`（name 唯一校验）、`DELETE /categories/:id`（仅自定义且无素材引用，或改为停用 `enabled=false`——推荐软删）。
- schema 变更：VideoCategory 加 `enabled Boolean @default(true)`；所有候选池/表单/拆句 prompt 过滤 `enabled=true`。
- 拆句 prompt 的分类清单本来就是动态注入（D11），新建分类即刻参与判定，无需额外开发。
- **运营提示写进界面**：新建分类只影响"句子判定与素材归类"；某货号要用新分类出片，得先有该货号+该分类的素材（否则全 gap）。

## 3. 表结构与接口变更汇总

- schema：`VideoCategory.enabled` 新增；`VideoExportTask.params` 扩展（subtitleStyle/bgm）；旁白文件挂 MediaFile，无新表。
- 接口新增：`POST /timelines/:id/rematch`、`POST /scripts/:id/tts`、`GET /materials/stats`、`POST|DELETE /categories`。
- VideoTimeline.status 流转补充：`matched → edited → exporting → exported`。

## 4. 风险

| 风险 | 预案 |
| --- | --- |
| edge-tts 限流/失效 | 重试 + 失败句静默降级；同时把"火山引擎 TTS"通道适配器做成可选实现（配置切换） |
| 时间线编辑器范围膨胀 | 严格按 F1 交互清单验收，帧级精剪、多轨道等一律 P3+ |
| BGM 版权 | 只放自有/可商用曲库并在仓库留来源说明；不做用户上传 BGM（P3 再评估） |
| 复核规则收紧后通用池变薄 | 上线前跑一遍 stats 看通用素材存量；不足的先人工批量复核 |

## 5. P2 完成后的短板（引导 P3）

单次要一条条出片；成片无品牌包装（片头片尾/文字动效）；素材量大后候选清单截断可能漏掉好素材（靠 embedding）；段时长精调不到帧级；无导出模板参数保存。
