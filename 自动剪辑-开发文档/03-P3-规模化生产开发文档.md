# P3 · 规模化生产开发文档

> P3 的定位与 P1/P2 不同：不是"一次排期做完的版本"，而是**按触发条件逐项启动的能力升级**。每项独立立项、独立验收，本文档定义各项的范围、触发条件与技术方案要点，供启动时细化。

## 1. 候选能力与触发条件

| # | 能力 | 触发条件（满足其一即立项） |
| --- | --- | --- |
| F1 | 批量出片 | 日均出片需求 ≥10 条，或运营提出"一个文案模板 × 多货号"玩法 |
| F2 | Remotion 模板包装 | 市场侧要求片头片尾、品牌字样、文字动效等统一包装 |
| F3 | embedding 语义召回 | 活跃素材 >2000 条（候选清单截断开始丢素材），或人工换素材率 >30%（说明 LLM 直接挑不准） |
| F4 | 标签运营 | 素材库 >5000 条，或出现"低质素材反复被选中"的投诉 |
| F5 | 安装包分发与自动更新 | 需要给非开发同事装机（当前如果是仓库跑法则一直不触发） |

## 2. F1 批量出片（预估 5d）

**形态**：批量任务页，创建任务 = 选文案（可多条）× 选货号（可多个）→ 笛卡尔积生成 N 个 VideoScript 副本（文案里的占位符 `{货号}` 替换为实际货号）→ 逐个跑 拆句→匹配→导出 全自动流水线。

**要点**：
- 新表 `VideoBatchJob`（任务定义、子任务 ID 列表、汇总状态）；子任务复用 P1/P2 全部流水线，**零新逻辑**。
- 串行执行（ffmpeg 与 LLM 并发过高没有意义），单子任务失败不阻断队列，汇总页展示每个子任务结果与缺口。
- 文案占位符替换发生在拆句**之前**（`{货号}`、`{品类}` 两个够用）。
- 验收：10 货号 × 1 文案 一键排队，无人值守出 10 条片，每条的货号素材互不串款。

## 3. F2 Remotion 模板包装（预估 8-12d，含模板设计）

**形态**：成片从"素材裸拼"升级为"模板渲染"——片头品牌字、卖点文字动效、片尾关注引导、安全区/画中画布局。

**要点**：
- Remotion 跑在 server 侧 Node 进程（`renderMedia`），输入 = 时间线 JSON + 模板 ID；前端技术栈同源（React 组件写模板），模板放 `server/src/video/templates/`。
- 与 ffmpeg 的关系：P1/P2 的 ffmpeg 链路保留为"快速粗剪"档；Remotion 为"包装成片"档，导出参数里二选一。**不要**试图用 Remotion 重写素材裁切（性能不划算），素材段仍由 ffmpeg 预拼，Remotion 只做包装层叠加。
- 模板变量：色板、logo 图、字体、文案动效样式，存 `VideoExportTask.params.template`。
- 风险：Remotion 公司许可（公司内部使用免费，商用需 Company License——按公司规模确认）；渲染耗时约为片长的 3-10 倍，批量任务要考虑夜间跑。

## 4. F3 embedding 语义召回（预估 4d）

**形态**：候选池从"全量塞清单"升级为"向量召回 top-K → LLM 精排"，直接复用知识库模块的 pgvector + embedding 地基（`KbChunk.embedding` 同款）。

**要点**：
- schema：`VideoMaterial` 加 `embedding Unsupported("vector")?`；打标完成后用 description（可拼 shotType/motion）生成向量。
- 检索：句子的 `visualNote` 向量化 → 在该句候选池（货号/通用的结构化过滤**不变**，D4 的规则永远先过滤再召回）内取 top 20 → 进 LLM 匹配 prompt。
- embedding 通道复用 `video/llm.ts` 加 kind="embed"，配置进 VideoSetting。
- 存量素材：后台任务补算（限速跑，避免 embedding 账单刺峰）。
- 验收：同样文案下，人工换素材率显著下降（以 P2 编辑器埋点的换素材率对比）。

## 5. F4 标签运营（预估 3d）

- 素材使用数据看板：`useCount`（被采用次数）、最近使用时间、从未使用素材清单——推动下架或补拍。
- 低质素材治理：打标结果加 `quality` 字段（VLM 顺带评：模糊/过曝/抖动），低质的自动排除出候选池（规则：quality=bad && 人工未豁免）。
- 打标 prompt 版本管理：prompt 改动记录在代码里（git 即可），重打标按钮支持按批次全量重跑。

## 6. F5 安装包分发（预估 3d，触发时做）

- Electron 目录已存在；要做的是：ffmpeg/ffprobe 打进 `resources/`（对应 00 文档 §3 的二进制定位第 2 条路径）、自动更新通道（electron-updater + 内部静态文件服务器）、首启动引导（server 地址/登录）。
- 注意 AGPL-3.0 传染性（原方案文档第 9 节）：对内使用无碍，若对外分发需法务确认，并保留原作者信息与前端标识。

## 7. 排期建议

P3 各项独立，建议顺序按触发条件自然驱动；若同时多项触发，优先级：**F5 > F1 > F3 > F2 > F4**（分发是其他人用起来的前提；批量是业务价值最大项；embedding 是质量兜底；包装最贵且依赖设计资源）。
