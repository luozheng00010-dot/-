# 素材标注结构化约束方案（颜色 / 环境分类 / 动作）

> 状态：待评审，未实施。讨论稿定稿于 2026-09-24。
> 前置阅读：00-总体设计与数据模型（标注与索引结构）、02-P2（画面查询与精排）。
> 配套已落地的基础：全局色板归一化（`normalizeColors`）、画面查询的关键词召回 + LLM 精排勾选框。

## 1. 背景与问题

素材标注当前是自由文本，视觉模型对同一事实造不同词，直接后果是**向量稀释**（一条素材一个整注向量，细节被平均）和**关键词召回失效**（查询词与标注词字面不匹配）：

| 字段 | 现状乱象（真实库抽样） | 影响 |
|---|---|---|
| 颜色 | 同一橙色写"橘色/橙色/桔色/暖橙"，还混入"棕（书架）/原木色（家具）"等场景色 | 按颜色搜索和"粉色这款"类文案匹配不可靠 |
| 环境 | 模特类画面有时写"白色人体模型"、有时写"模特"、有时不写 | "模特展示"类语义单元只能靠向量猜 |
| 动作 | "拂过/抚过/轻抚/搓过"同义混战，句式长短不一 | 动作类查询（画面查询的核心场景）排序抖动 |

## 2. 总体原则

1. **封闭集合 + 商家真值 = 硬约束；开放集合 = 软收敛。** 颜色和环境的取值集合是封闭、由商家定义的（产品色款、公司拍摄规范），适合硬约束；动作是开放组合的，硬约束会导致漏标，只做软收敛。
2. **三道防线同一骨架**：提示词约束（源头）→ 落库归一（防漏网）→ 结构化字段进索引与召回（兑现价值）。
3. **诚实兜底**：宁可标"其他/待人工"，不允许硬塞进错误分类——错误分类比未分类伤害大（搜错 vs 搜不到）。
4. **存量数据永远有便宜迁移路径**：能不重跑视觉就不重跑。

## 3. 颜色：货号级硬约束

### 3.1 数据模型

- `LocalVideoSku` 新增 `colors Json`（字符串数组，可空）。空 = 该货号未填色款，回落全局色板（现有行为）。
- 建货号/编辑货号时提供颜色输入（tags 输入框，自由添加）。货号管理入口在素材库页（现有 SKU 下拉旁增加管理入口，或并入管理设置页）。
- 标注 JSON 的 `colors` 字段语义变为：**产品主体颜色，取值应尽量来自该货号色款清单**。

### 3.2 分析链路（analyze）

提示词注入（货号有清单时）：

```
该产品的在售色款为：粉、米、灰、黑。colors 必须从这些色款中选取最接近的（可
多选，如对比镜头），不允许发明清单外色名；画面颜色与所有色款都不像时，选最接
近的并在 warnings 中注明"疑为样品色/打光偏差"。
```

全局色板约束（已上线）保留，作为未填清单货号的兜底。

### 3.3 落库归一

现有 `normalizeColors`（同义词映射→标准色名）之后，追加一步**清单对齐**：归一后的色名若不在货号清单内，保持原值但计入 warnings"不在色款清单"（供商家发现并补填清单或修正模型），**不做强制改写**（避免商家清单本身漏填时错改标注）。

### 3.4 兑现价值

- 画面查询：颜色词进入关键词精确召回（已实现"词"角标）；搜索页增加**颜色 chips 筛选器**（选项 = 当前货号的色款清单），与 LLM 精排组合出"粉色 + 手拂过"式检索。
- 方案匹配：候选重排 prompt 中 colors 已随标注传给模型，色款对齐后 structured 信号更稳。
- 素材库：可按颜色筛选（同一份清单）。

### 3.5 存量迁移

1. 用户为现有 2 个货号补填色款清单（UI 操作）。
2. 已归一的 984 条老标注不重分析也能受益（色名已统一 + 清单对齐的 warnings 提示）；如需"只写产品主体颜色"的彻底干净，再择机批量重分析（见成本评估）。

## 4. 环境分类：全局硬约束

### 4.1 数据模型

- 标注 JSON 新增枚举字段 `setting`，取值默认 5+1：`手持 / 衣架 / 平铺 / 模具 / 硅胶 / 其他`。
- 清单为**全局配置**（管理设置页维护，默认值如上），不放货号级——这是公司拍摄规范，所有货号通用。
- 判别定义写入提示词（这是模具/硅胶不混的关键）：

| 取值 | 判别器 |
|---|---|
| 手持 | 画面中有真人手举着/拿着产品 |
| 衣架 | 产品挂在衣架、裤夹、挂钩上 |
| 平铺 | 产品平放于桌面、台面、床面 |
| 模具 | **纯白色**无肤色假体人（白躯干/白半身模特） |
| 硅胶 | **黄色/肤色**仿真假体人 |
| 其他 | 都不符合（如纯静物布景、包装展示） |

- 混合画面（前手持后平铺，1-2 秒素材少见）：取占比最大者，并在 warnings 注明。

### 4.2 分析链路

提示词注入固定模板 + 判别器表 + 兜底规则。落库时校验：模型返回了清单外取值 → 改写为"其他"并在 warnings 注明（防模型自造类）。

### 4.3 兑现价值

- 画面查询：setting 是天然筛选器——搜索页加**环境 chips**（手持/衣架/平铺/模具/硅胶），与颜色 chips、LLM 精排三维组合。
- 方案匹配：`candidatesFor` 的标签精确召回把 `setting` 纳入（文案"模特展示"→模具/硅胶）；重排 prompt 显式给出 setting 字段。
- 动作治理：setting 是动作动词表分组的依据（见第 5 节）。
- 结果卡片：setting 显示为小角标（比颜色更一眼可辨）。

### 4.4 存量迁移（便宜路径，不重跑视觉）

已有约 1000 条标注的 `summary/scene` 大多明确写着"白色人体模型""挂在珍珠衣架上""平铺在桌面"：

1. 迁移脚本读取旧标注，调用**文案模型**（非视觉模型）按判别器表归类，一次批量调用（可分批，每批 20 条）。
2. 低置信/矛盾的标 `其他` 并进入"待人工确认"。
3. 只更新 `setting` 字段 + 重建索引（复用颜色迁移的 revision/index 机制）。
4. 成本：约 50 次文字调用，不到一次视觉重分析的 5%。

## 5. 动作：软收敛（不做硬约束）

### 5.1 动词表（全局，按 setting 分组注入）

| 环境 | 推荐动词 |
|---|---|
| 通用 | 展示、拿起、提起、翻动、悬挂、推移、旋转、对比 |
| 手持 | 轻抚、划过、拉伸、按压、捏起、捋平、撑起 |
| 模具/硅胶 | 穿着展示、静态呈现、整理、上身、提拉 |
| 衣架 | 悬挂展示、取下、翻动 |
| 平铺 | 铺平、折叠、展开、抚过 |

提示词规则：actions 写"动词+对象"短句（如"手指轻抚腰头"），动词优先从当前环境的分组中选；表外动词**允许**但属于少数派——开放集合不禁止，只引导。

### 5.2 落库

不做强制归一（组合开放，硬映射会误伤），仅去重/去空白。同义动作（拂过 vs 抚过）靠下面的检索层解决，而非标注层。

### 5.3 动作独立向量（检索层，方案 B）

当前一条素材只有一个"整注向量"，动作细节被 summary/scene 稀释。改为双向量：

- `embedding`：整注 JSON（现状不变，画面查询/方案匹配继续用）。
- `action_embedding`：`actions` 数组拼接文本的向量，查询时与整注向量**双路召回取并集**，actions 向量命中的结果同样参与排序（距离与整注距离分不可比，并集后排序规则：词命中 > 任一向量命中按各自距离归一）。
- 索引任务一次调用 embed 两段文本（embedding-3 支持数组输入，成本不变）；新增列 + 索引重建为一次性。
- 索引版本机制：`embedding_identity` 从"渠道 key"扩展为"渠道 key + 结构版本号"，结构升级后老索引自动判废重建（沿用现有 key 不匹配即重建的机制，只是 key 的构成变化）。

### 5.4 精排兜底

画面查询已上线的 LLM 精排勾选框是动作检索的最终保险：开放词表下，让模型读动作原文判断相关性，比任何字面/向量手段都灵活。

## 6. 端到端数据流（实施后）

```
上传（货号+可选备注）
  → analyze：抽帧 → 视觉模型（注入：货号色款清单 + 全局环境表与判别器 + 分环境动词表）
  → 结构化标注 { summary, parts, actions, setting, colors(色款对齐), ... }
  → index：整注向量 + 动作向量（双路）
  → 画面查询：颜色 chips × 环境 chips × (向量近邻 + 词命中) → 可选 LLM 精排
  → 方案匹配：单元 query 向量召回 + tags/setting 精确召回 + 模型重排（含 setting/colors 结构化信号）
```

## 7. 实施顺序与里程碑

建议按依赖与性价比排序，每步独立可发布、独立验收：

| 步骤 | 内容 | 主要改动面 | 验收标准 |
|---|---|---|---|
| M1 颜色 | SKU.colors 字段 + 货号管理 UI + 提示词注入 + 清单对齐归一 | server schema/routes、web 货号 UI、analyze prompt | 新建带清单货号上传素材，标注 colors 全部落在清单内；搜索"粉色"词命中生效 |
| M2 环境分类 | setting 字段 + 全局配置 + 提示词判别器 + 存量批量归类迁移 + 搜索 chips | annotation schema、analyze prompt、迁移脚本、web 搜索页 | 存量 ≥90% 自动归类；搜索页按"硅胶+动作"组合检索结果精准；模具/硅胶抽检不混 |
| M3 动作 | 分环境动词表 + 动作向量列 + 双路召回 | index 任务、检索 SQL、embedding 版本机制 | "手拂过内裤"类查询前 5 名动作命中率明显高于现状（用同一批查询词前后对比） |

M1/M2 可并行；M3 依赖 M2（动词表按 setting 分组）。

## 8. 兼容性与回滚

- 旧方案文档（plans）不含 setting 字段：解析时按 `其他` 处理，不影响渲染与匹配。
- `colors` 为空清单的货号：全程回落全局色板，行为与现状一致。
- 每个里程碑独立数据库迁移，可单独回滚；新字段均为新增（JSON 内新增键 / 新列），不动旧结构。

## 9. 测试计划

- 单测：清单对齐归一（含"不在清单→warnings 不改写"）、setting 校验（清单外取值→其他）、动词表注入的分环境断言、双向量并集排序规则。
- 路由测试：搜索带 setting/color 筛选、双路召回去重。
- 迁移脚本：先在 20 条样本上试跑并人工核对，再全量。
- 端到端冒烟：新建货号（带 3 个色款）→ 上传 5 条不同环境素材 → 验证标注 setting/colors 全部合规 → 搜索页 chips + 精排组合检索命中预期素材 → 建方案验证匹配提升。
- 回归：现有 pytest / vitest 全绿。

## 10. 成本评估

| 项目 | 规模 | 估算 |
|---|---|---|
| M2 存量环境归类 | ~1000 条，文字模型批量调用 | 约 50 次调用，元级 |
| M3 动作向量重建索引 | ~1000 条，embedding 双路 | embedding 按 token 计费，元级 |
| M1 颜色重分析（可选，非必须） | ~1000 条 × 视觉模型 | 有实际 vision token 成本，建议只在 M1 上线后效果不达标时执行 |

常态新增成本：无——三道防线都在标注入库时一次性完成，检索侧只是多一个枚举字段过滤。
