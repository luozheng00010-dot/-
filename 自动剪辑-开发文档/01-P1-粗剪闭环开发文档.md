# P1 · 粗剪闭环开发文档

> 前置阅读：`00-总体设计与数据模型.md`（表结构、JSON 结构、接口总表）。
> P1 目标：**一条链路跑通**——批量上传素材 → AI 打标入库 → 选货号贴文案 → 拆句匹配 → ffmpeg 拼出带字幕的粗剪 mp4。

## 1. 验收标准（Definition of Done）

1. 批量上传某货号素材 100 条（1-5 秒/条），10 分钟内全部完成打标入库（VLM 并发 ≥2），批次页能看到 done/failed 计数；失败条目有明确错误信息且可单独看到。
2. 新建创作：选货号、贴 300 字左右文案 → 拆句（每句带分类判定与预估时长，前端可改）→ 匹配 → 生成时间线；每句展示所用素材缩略图卡片与匹配理由。
3. 找不到/凑不齐素材的句子在时间线上标红，悬停可见缺口原因（如"货号 A123 无『文胸』分类素材"）。
4. 提交导出后 5 分钟内得到 1080×1920 竖版 mp4：镜头顺序正确、字幕已烧录、无音轨；导出过程有进度百分比；成片可在页面下载。
5. 解耦验收：删除 `modules/video-edit` 目录、`app.use("/api/video")` 一行、worker 启动调用后，`pnpm build` 通过、画布与知识库功能不受影响。

## 2. 范围

**范围内**：批量上传与异步打标、素材库列表页（筛选/进度）、创作页（拆句预览可微调 + 只读时间线）、导出任务与进度、烧录固定样式字幕、缺口标红。

**范围外（P1 明确不做）**：时间线拖拽编辑、TTS 旁白、BGM、转场、字幕样式选择、分类管理 UI（用 seed 三条）、打标人工校准页（仅留 PATCH 接口）、embedding、镜头切分、批量出片。

## 4. 关键技术规格

### 4.1 VLM 打标

抽帧：`ffmpeg -ss <duration/2> -i input -frames:v 1 -q:v 3 out.jpg`，缩略图经 sharp 压到短边 480 再传 MediaFile。

Prompt（vision，system）：

```
你是电商视频素材管理员。看这张视频抽帧，输出 JSON：
{
  "category": "文胸|内裤|其他",     // 从给定清单中选：{{categories}}
  "shotType": "特写|近景|中景|全景",
  "motion": "旋转|手持|摆放|穿戴|平铺|使用演示|其他",
  "productVisible": true|false,     // 画面是否出现可识别的具体产品（内衣本体）
  "description": "一句话中文画面描述，不超过30字"
}
只输出 JSON。
```

- `category` 与上传时人工选的分类**不一致**时：以人工为准，但 description 里追加提示"（疑似X类）"，素材详情里展示，供 P2 校准。
- `productVisible=true` 且分类=通用：**不阻断入库**，但 `reviewStatus` 标记待复核提示（前端黄标提示"疑似露出产品，请人工确认"），P1 仅提示、P2 做复核队列。
- 帧图同时发给 VLM 前先压尺寸，控制 token 成本。

### 4.2 拆句（chat）

Prompt（system）骨架：

```
你是短视频文案分镜师。把文案拆成逐句分镜，输出 JSON：{"sentences":[SentencePlan]}。
规则：
1. 按语义断句，每句 8~25 字；
2. 为每句判定 needCategory，只能从这些分类中选：{{categories}}（其中"通用"=不出现产品的画面：穿衣动作、场景氛围、开场结尾）；
3. 产品卖点句（面料/工艺/版型/上身效果）→ 选产品所属分类；穿搭/氛围/引导句 → 选"通用"；
4. durationHint = 字数 ÷ 4.5，保留 1 位小数；
5. visualNote 用一句话描述理想画面，给后续素材匹配用。
```

### 4.3 匹配（chat）

Prompt（system）骨架：

```
你是剪辑师。给你：①分镜句列表（含 needCategory / durationHint / visualNote）
②候选素材清单（每条：materialId / 分类 / 时长秒 / 描述 / 景别 / 动作）。
为每句挑 1~4 条素材按播放顺序拼满时长，输出 {"items":[TimelineItem]}。
硬规则：
1. needCategory="通用" 的句子只能用清单中分类="通用"的素材；
2. 其他句子优先用"货号素材且分类=needCategory"的素材；不够时可用同货号其他分类素材顶替并标 downgraded=true；
3. 每段素材整条使用（outPoint=该素材时长），只有最后一段允许裁剪来对齐总时长；
4. 各段时长之和与 durationHint 差值 ≤0.3s；素材都不够时如实留 gap，禁止编造 materialId；
5. 挑选时优先考虑 visualNote 与素材描述的贴合度，写清 reason。
```

服务端校验（zod + 业务检查，不过关整体重试 1 次，仍失败任务 failed）：
- `materialId` ∈ 候选池且该素材 `status=active`；
- 段时长 0.5s ≤ out-in ≤ 素材时长；
- 句子时长和 ∈ durationHint ±0.3s（最后一段自动 clamp 到位）；
- 通用句用了货号素材 → 直接判非法。

### 4.4 ffmpeg 合成

三步，全部在临时目录进行，结束清理：

```bash
# ① 逐段标准化（裁剪 + 统一分辨率/fps + 去音轨）
ffmpeg -y -i <素材> [-ss <in> -t <len>]
  -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2,fps=30,setsar=1,format=yuv420p"
  -an -c:v libx264 -preset veryfast -crf 20 seg_<n>.mp4

# ② 拼接
ffmpeg -y -f concat -safe 0 -i list.txt -c copy body.mp4

# ③ 烧字幕（ASS，服务端按时间线生成，含逐句起止时间）
ffmpeg -y -i body.mp4 -vf "ass=subs.ass" -c:v libx264 -preset veryfast -crf 20 out.mp4
```

- 句子起止时间 = 前面所有句子的 `duration` 累加；有 gap 的句子直接跳过（画面和字幕都不出现），并在导出结果页注明"跳过 N 句缺口"。
- ASS 样式（P1 固定）：`Fontname=Microsoft YaHei`，字号 64，白字黑边，底部居中，`MarginV=220`。**Windows 下若 libass 找不到字体，改用 `fontsdir` 参数或回退 drawtext + fontfile**（开发时先验证 ③ 在目标 Windows 机器上的表现）。
- 进度：第①②步按段数线性映射 0-80%，第③步用 `-progress pipe:1` 的 `out_time_ms ÷ 总时长` 映射 80-100%。
- 成片命名：`{货号}_{script标题}_{yyyyMMdd_HHmm}.mp4`，存 MediaFile 后返回下载链接。

### 4.5 缺口判定逻辑（服务端，不依赖 LLM）

匹配完成后由服务端复核生成 GapReport：
- 句子候选池三层全空 → `no_candidate`；
- 段时长之和 < durationHint − 0.3s → `insufficient`，`missingSeconds` = 差值；
- LLM 自报 gap 与服务端复核不一致时，**以服务端为准**。

## 5. 页面规格（最小可用）

- **素材库 `/video-edit/materials`**：顶部"批量上传"按钮 → 弹窗（货号输入框、分类下拉、文件多选；分类=通用时货号自动填"通用"并置灰）；网格卡片（缩略图、时长角标、货号+分类 tag、打标状态、露产品黄标）；筛选条（货号模糊、分类、打标状态）；批次进度条常驻顶部。
- **创作 `/video-edit/create`**：步骤条 1-2-3。步骤 3 时间线只读：每句一张卡（字幕文本、时长、needCategory 色 tag），卡内横向排列段卡片（缩略图 + 秒数 + reason tooltip），缺口句整卡红边 + 原因文案；底部"提交导出"。
- **导出 `/video-edit/exports`**：任务列表（进度条/状态/错误），完成的行有下载按钮和"跳过 N 句"提示。
